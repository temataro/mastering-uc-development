Deeper detail: entry point is not the reset vector

ENTRY(Reset_Handler) sets ELF entry metadata. On a normal Cortex-M hardware reset, the processor's initial stack pointer and reset address come from the selected boot vector table. The CPU does not parse ELF headers. An N6 debug launch can instead load RAM and explicitly arrange registers and execution. Persistent N6 boot begins with ST's boot ROM and loads a first-stage image.

The ELF entry was 0x34180955, while disassembly labels the first instruction of Reset_Handler at 0x34180954. Bit 0 of an Arm Thumb function address denotes the instruction-set state; it is not an extra byte of code before the function.

02 · Address space versus physical storage

An address selects hardware. A section organizes software.

Your example: SRAM gets the first range, flash gets the next billion addresses, then AHB1 gets another range.

Your “patched together” intuition is right. The numerical allocation example is not. A 32-bit byte-addressed space contains 2³² byte addresses: 4 GiB, from 0x00000000 to 0xFFFFFFFF. It does not imply 4 GiB of installed storage.

Hardware decides

Memory bank ranges, peripheral base addresses, register offsets, aliases, and access rules. Find them in the exact MCU's reference manual.

The linker decides

Where code, constants, variables, vector tables, and stack reservations fit within usable memory. Your script cannot create SRAM at an arbitrary address.

Unused holes and reserved addresses exist. Two address ranges can alias the same storage, including Secure and Non-secure views on some devices. A dereference is a hardware transaction: a RAM read retrieves storage; a peripheral read queries register logic. Being expressible as a C pointer does not make it a valid access.

What the buses contribute

A bus/interconnect carries transactions between requesters and addressed resources. The CPU and DMA can be bus masters; memory controllers and peripheral interfaces respond to their requests. Bridges connect domains, such as an AHB-to-APB bridge. APB is a simpler peripheral-access protocol; AHB and AXI support different performance/features. A bus name is not itself a memory technology or a promise about a particular transfer speed.

Instruction fetches, data accesses, debugger accesses, and DMA transfers need not follow identical routes. They can contend for resources, encounter wait states, or face different permissions. The course's Cortex-M4 I-Code/D-Code/System-bus diagram is not a literal map of the Cortex-M55/N6 interconnect; use the N6 architecture diagram when porting.

ITCM is tightly coupled instruction memory, used for explicitly placed code. ITM is trace hardware. A cache automatically retains copies of accessed memory; ITCM placement is explicit. A function can use ITM while executing from ordinary SRAM.

Your local RM0486 Rev 2, §§2.3 and 3, describes the N6 map and security. Its filename is opaque; check document title/revision rather than guessing from the name. ST N657 register definitions confirm the RCC address above.

03 · Control and observation are different paths

SWD operates the debugger. SWO carries trace.

SWD = Serial Wire Debug, not “Serial Wire Debugger.” Its two signal pins are SWCLK and bidirectional SWDIO. SWO is a separate optional output. Ground, voltage reference, and possibly reset are additional connection requirements.

SWD is an alternative debug transport to JTAG, not a replacement for all JTAG uses such as boundary scan. Debug hardware can halt/resume the core, read registers/memory, and set breakpoints without your firmware polling a debug request.

ITM is the Instrumentation Trace Macrocell, part of the core's debug/trace subsystem. Its stimulus ports create tagged packets. Trace routing/serialization, pin configuration, clocks, probe reception, and host decoding must all agree.

Your phrase “program counter on your computer” needs changing: the target CPU's PC controls the firmware. The host asks the target to stop and displays its state. General registers hold working values, SP identifies the current stack position, and LR usually carries a return address or an exception-return encoding.

SFR is a view of hardware semantics

SFR = Special Function Register. A peripheral register can be read-only, write-only, read-to-clear, or write-one-to-clear. Its documentation defines the meaning of each bit. “Write 1” does not always mean “set the stored bit to 1.” A debugger read can consume data or clear a status flag on some registers; avoid continuously refreshing those while investigating an event.

volatile tells the compiler that accesses are observable and must follow its volatile-access rules. It does not make a read-modify-write atomic, configure memory permissions, fix cache coherency, or turn a reserved address into a usable register.

Halting the CPU need not halt the whole MCU. Timers, DMA, and external devices may continue. Peripheral debug-freeze behavior is device-specific. A stopped snapshot can therefore differ from uninterrupted behavior.

06 · Keep the F407 and N657 clock trees separate

Oscillators generate. PLLs derive. Prescalers divide.

HSE is the high-speed external source: a crystal with the MCU's oscillator circuitry, or an externally supplied clock in bypass mode. HSI is an internal RC oscillator. PLL is a phase-locked loop deriving an output from a source through multiplication and division, within specified limits. It is not an independent oscillator.

“Most MCUs have exactly these three choices” is too broad. STM32 families can also include MSI, low-speed sources, and multiple PLLs. An MCU can run different domains and peripherals from different clocks.

AHB = Advanced High-performance Bus. APB = Advanced Peripheral Bus. HCLK is the AHB clock; PCLK is an APB-domain clock. On F407 HCLK also clocks the core. On N657, do not equate CPU frequency with HCLK or the trace clock.

Prescalers divide; they do not multiply. F407 timer clocks normally equal PCLK when the APB divider is 1, and equal 2 × PCLK otherwise. That is a timer-domain rule, not evidence that the APB prescaler multiplies.

CPU MHz measures clock cycles per second, not completed instructions per second. Instruction complexity, memory wait states, cache misses, and bus contention affect execution time. Raising frequency can also require power/voltage and memory-latency changes; a divider calculation alone is not a complete clock configuration.

07 · The clock gate belongs to the peripheral

RCC is a register block, not one register.

Your clock-gating explanation is nearly right. Many peripheral clocks are disabled after reset to save power, but defaults vary and boot ROM/startup may already have enabled some.

There are two separate decisions: the frequency reaching a domain and whether a particular peripheral receives a clock. A bit in an RCC enable register usually gates one peripheral, not every peripheral on that bus.

Domain clock ──┬── [GPIOG gate: enabled] ── GPIOG register/logic clock
               ├── [GPIOH gate: disabled] ── GPIOH
               └── [another individual gate] ── another peripheral

A clock gate is also distinct from peripheral reset, pin alternate-function selection, peripheral enable, and its communication clock source. On N6, some blocks have a bus interface clock and a separate kernel clock; access/security settings can matter too.

08 · Two special words before ordinary IRQ vectors

The vector table begins with a stack value.

Your model: “These are all pointers to exception handlers.”

The active vector table supplies exception entry addresses. On the reset path, hardware obtains an initial MSP and reset entry from the boot table. VTOR identifies the active table used for exceptions; TrustZone systems have Secure and Non-secure tables.

On N6, normal reset first runs ST boot ROM. Your RAM debug image is not automatically the reset boot image merely because its linker says ENTRY(Reset_Handler). Boot or the debug launch must arrange handoff, including the applicable vector base.

NRST is active low. Reset may also come from power-on logic, a watchdog, or software. Reset starts initialization again; it is not an ordinary peripheral IRQ to enable through NVIC. Architecturally reset has the highest fixed priority, then NMI, then HardFault.

09 · Routing, selection, and linkage

A handler name is resolved before the program runs.

Exceptions include faults and other system events, as well as peripheral interrupts. SysTick, SVC, and PendSV are not necessarily errors. An ADC conversion normally sets status and makes data available; DMA moves data only if separately configured.

A peripheral interrupt must become pending and be eligible for service. Priority, enable bits, masking, current execution, and security affect eligibility. A smaller programmable priority number generally means higher urgency; preemption also depends on priority grouping. Do not equate IRQ number with priority.

On basic exception entry, hardware stacks working registers, LR, the return PC, and xPSR. Floating-point/security features can add state. It reads the selected vector and runs a handler, then restores the interrupted context on exception return. This is hardware-assisted control flow, not a C function polling the vector table.

PM0273: Cortex-M55 exception behavior CMSIS: NVIC enable, priority, pending state

What “weak” actually means in your startup file

Startup object:
  vector entry refers to Some_IRQHandler
  weak Some_IRQHandler aliases Default_Handler

Your object, when supplied:
  strong Some_IRQHandler defines your handler

Linker:
  resolves the name to your strong definition
  writes its final address into the vector entry

The NVIC does not inspect C names or choose between weak and strong functions at runtime. You normally replace the default by defining the exact expected symbol and linking it. This differs from modifying a RAM vector entry at runtime. A HAL handler may call a callback, but bare-metal interrupt dispatch does not require that extra layer.

Servicing an interrupt usually includes acknowledging the peripheral's source according to its register semantics. Clearing only NVIC pending state can leave the source asserted and cause immediate re-entry.

10 · Hardware security does not imply automatic verification

Isolation and authenticity answer different questions.

MechanismQuestion answeredWhat it does not mean
TrustZoneWhich execution state may access a resource?Code in Secure memory is not automatically signed, correct, or trustworthy.
Secure bootDoes a boot image satisfy the configured authenticity/integrity policy?Not the same operation as partitioning runtime access.
Secure GatewayWhere may Non-secure code enter a Secure service?A function attribute alone does not configure its memory region.
Resource isolation / memory protectionWhich masters/contexts and accesses are allowed?CPU security state is not the only access condition on N6.

TrustZone uses Secure and Non-secure execution on the same CPU. Secure/nonsecure is also distinct from privileged/unprivileged. Hardware enforces configured access boundaries. Secure memory is an attributed region, not necessarily a different physical chip or memory technology.

Your N657's boot ROM and security architecture differ substantially from the course's F407. The onboard F723 is the ST-LINK probe MCU; it is not a second TrustZone execution world.
